Тестовое задание: копия YouTube
Привет! Мы — команда, в которой код пишут ИИ-инструменты (Claude, Cursor, ChatGPT), а инженер — архитектор, ревьюер и постановщик задач.
Задание проверяет: архитектурное мышление (цель → решения и собственные критерии «что значит работает правильно»), проектирование системы в целом (данные, хранилище, безопасность, эксплуатация), работу с объектным хранилищем, автотесты критичного поведения и навыки настройки ИИ в разработке — промпты, декомпозиция, проверка результатов.

На выполнение дается 10 дней с момента получения.
Задание
Через ИИ создать копию YouTube — насколько сможете.
YouTube — сервис, который знают и которым пользуются все: не нужно читать требования и разбираться, что должно работать — вы и так это знаете.
Экраны:
    • Главная — лента видео с превью
    • Просмотр видео — плеер, лайки, комментарии
    • Канал — видео и плейлисты автора, подписка
    • Поиск — по названию
    • Загрузка — выбор файла, прогресс, метаданные
    • Вход и регистрация
    • Модерация — жалобы и скрытие видео

Требования к начинке:
    • загрузка, хранение и раздача видео — сердце системы
    • роли: пользователь, модератор, администратор
    • приватные видео — только тем, кому разрешил владелец

Фиксировано немногое:
    • Python + FastAPI, PostgreSQL; Swagger (/docs); экраны — простой фронт
    • весь код — через ИИ, промпты сдаются вместе с кодом
    • деплой на чистой Ubuntu одной командой

Что сдать
Результат присылаете в виде zip-файла, внутри которого:
    • сам код — front-end, back-end, инфраструктура — как git-репозиторий целиком, вместе с каталогом .git и всеми коммитами: по истории коммитов видно, как вы работаете с git. Не чистите историю и не склеивайте всё в один коммит.
    • файлы диалогов с ИИ, которые вы использовали для создания этого проекта, — строго в исходном формате, который генерирует сам инструмент (как — ниже);
    • вся агентная обвязка, которой пользовались: агенты, скиллы, правила, настройки — всё.

Диалоги берите строго из файлов, которые создают сами инструменты, — без пересказов, копипасты и скриншотов. Нам нужны только те диалоги, которые вы использовали для решения этого задания, — остальные ваши переписки не нужны и мы их не просим. Каждый инструмент хранит историю диалогов в специальном формате:
    • Cursor — экспорт чатов: Cursor Settings → Chats → Export all chat data; в архив положите чаты, относящиеся к этому проекту;
    • Claude Code — файлы сессий из каталога ~/.claude/projects/<проект>/ — это ровно диалоги этого проекта: скопировать в архив все *.jsonl целиком;
    • ChatGPT и Claude (веб) — экспорт данных: Settings → Data controls → Export data; приложите из него диалоги, относящиеся к этому заданию;
    • агентная обвязка — все файлы, которыми вы настраивали ИИ, как есть, без чистки:
◦ Cursor — AGENTS.md в корне проекта и каталог .cursor/: rules/, skills/, commands/, mcp.json;
◦ Claude Code — CLAUDE.md, каталог .claude/: agents/, skills/, commands/, settings.json, плюс .mcp.json из корня проекта;
◦ другие инструменты — их аналоги: файлы правил, скиллов, агентов и подключений MCP.

Для нас ключевое — получить именно ваши диалоги по этой задаче и обвязку в исходном виде: по ним мы видим, как вы мыслите и как работаете с ИИ. Код без них — половина результата.
Как мы проверяем
Мы разворачиваем вашу систему на чистой виртуальной машине для тестирования и проверяем:
	1.	Объём — сколько вы успели сделать.
	2.	Соответствие оригиналу — насколько копия похожа на YouTube: дизайн, расположение элементов и так далее.
	3.	Разворачиваемость — всё разворачивается на чистой Ubuntu одной командой: приложение, БД, хранилище, фоновая обработка. После развертывания сразу работает сценарий «регистрация → загрузка → просмотр → лайк и комментарий». В архиве — README, docs/, автотесты и скрипт наполнения базы демо-данными (пользователи, видео, комментарии), чтобы систему можно было проверить целиком.
	4.	Архитектура — какую архитектуру вы придумали и применили для этого приложения.
	5.	Проектирование БД — как вы спроектировали базу данных: схема, связи, что и где хранится.
	6.	ИИ и обвязка — как настроили искусственный интеллект и агентную обвязку.
	7.	Безопасность — насколько всё защищено с точки зрения ИБ.
	8.	Git — как вы работаете с git: осмысленная история коммитов.
