# Клон YouTube

Сайт для обмена видео в стиле YouTube, который разворачивается на чистой машине с Ubuntu одной
командой. FastAPI, PostgreSQL, MinIO, воркер на ffmpeg и фронтенд на React за nginx. Дизайн,
схема БД, матрица прав и проверки всего, что заявлено ниже, описаны в
[docs/architecture.md](docs/architecture.md).

## Что умеет

- **Видео:** загрузка с индикатором прогресса, перекодирование в HLS в 360p и 720p с
  миниатюрой и воспроизведение по короткоживущим подписанным ссылкам. Публичные, по ссылке и
  приватные видео, а также приватные видео, к которым открыт доступ выбранным пользователям.
- **Просмотр:** главная лента, поиск, страница просмотра с блоком «Следующее», лайки и
  дизлайки, комментарии и счётчик просмотров с дедупликацией.
- **Каналы:** страницы каналов с видео и плейлистами, подписки и лента подписок.
- **Плейлисты:** создание, изменение порядка, воспроизведение по порядку; сохранение со
  страницы просмотра.
- **История:** история просмотров с местом, где вы остановились.
- **Модерация:** жалобы, очередь модераторов, скрытие и восстановление видео с журналом
  действий, а также управление пользователями для администратора (роли, блокировка).
- **Внешний вид:** раскладка как на YouTube, аватары-буквы и тёмная тема, которая следует
  за системной.

## Запуск

На чистой машине с Ubuntu (протестировано на 24.04), из корня репозитория:

```bash
./install.sh
```

Это единственный шаг. Скрипт при необходимости устанавливает Docker, генерирует секреты в
`.env`, собирает и запускает все сервисы, применяет миграции, создаёт бакеты хранилища и
наполняет сайт демо-данными. В конце он выводит адрес сайта. Повторный запуск безопасен:
данные, секреты и демо-пароли сохраняются.

На чистой виртуальной машине с Ubuntu 24.04 (4 CPU, 8 ГБ) путь от `git clone` до
напечатанного адреса занял меньше трёх минут, без каких-либо других шагов; после этого
дымовой тест и проверка демо-данных прошли успешно. CI повторяет установку на чистых
машинах при каждом push.

| Параметр | Действие |
|---|---|
| `--no-seed` | Запустить пустой сайт, без демо-данных |
| `HTTP_PORT=8081 ./install.sh` | Использовать другой порт вместо 80 (только при первом запуске; значение сохраняется в `.env`) |
| `--domain example.com` | HTTPS с сертификатом Let's Encrypt, HSTS и Secure-cookie (см. ниже) |
| `--no-domain` | Вернуться к обычному HTTP после `--domain` |

### HTTPS с доменом

```bash
./install.sh --domain videos.example.com
```

Сначала направьте DNS домена на машину и откройте порты 80, 443 и 443/udp. Затем перед nginx
встаёт Caddy: он получает и продлевает сертификат, перенаправляет HTTP на HTTPS и добавляет
HSTS; сайт доступен по адресу `https://videos.example.com`. Выбор сохраняется в `.env`,
поэтому обычный повторный запуск его сохраняет, как и `docker compose`, запущенный из
корня репозитория. `./install.sh --no-domain` возвращает обычный HTTP. Caddy и nginx
общаются через небольшую сеть Docker `10.213.67.0/29`; если на машине этот диапазон уже
занят, измените его одновременно в `compose.domain.yaml` и `infra/nginx/real_ip_tls.inc`.

### Это демо-окружение

`install.sh` разворачивает окружение для **оценки и тестирования**, а не для продакшена:

- Он создаёт демо-каналы, видео и аккаунты, **включая администратора**. Пароли у них
  случайные и сохраняются в `demo-credentials.txt`, который доступен для чтения только
  пользователю, запустившему скрипт.
- Без `--domain` сайт работает по обычному HTTP на IP-адресе машины, поэтому логины в
  передаче не шифруются. Кроме того, браузеры разрешают микрофон только на защищённых
  страницах, поэтому голосовой поиск появляется с `--domain` (или на `localhost`), но не
  на адресе с обычным HTTP.

### Демо-данные

Пять каналов с двенадцатью настоящими видео и девятью Shorts, три аккаунта зрителей, которые
ставили лайки, писали комментарии, подписывались и создавали плейлисты, и администратор.
Видео распространяются свободно, а в описании каждого указаны источник и лицензия:

- **Launch Pad, Sun Watch, Blue Planet Lab:** ракеты, солнечные вспышки, Земля, Луна и Марс
  из [публичного архива NASA](https://images.nasa.gov) (общественное достояние; NASA
  здесь ничего не поддерживает).
- **Open Movie Night:** трейлеры Sintel и Big Buck Bunny, открытых фильмов Blender
  Foundation (CC BY 3.0).
- **Shorts:** вертикальные ролики с [Wikimedia Commons](https://commons.wikimedia.org):
  таймлапсы спутников NOAA и визуализации NASA (общественное достояние), а на канале
  **Wild Water** водопады и птицы (CC0 и CC BY).

Установка скачивает их (около 170 МБ) и проверяет каждый по SHA-256, закреплённому в
`backend/app/services/seed.py`, поэтому в репозитории нет видеофайлов. Если видео скачать
не удалось (нет интернета, хост недоступен), вместо него создаётся сгенерированная
заставка, и установка всё равно завершается успешно. Загрузки хранятся в томе Docker,
поэтому при повторном запуске они не скачиваются заново. Названия каналов и зрителей
выдуманы. Видео проходят через тот же конвейер загрузки и перекодирования, что и любая
загрузка. Войти можно с любым аккаунтом из `demo-credentials.txt`.

## Как всё устроено

```text
browser ─► nginx ─┬─► SPA (built React app)
  (Caddy first,   ├─► /api ─► api (FastAPI) ─► PostgreSQL (data and the job queue)
   with --domain) ├─► /hls, /thumbs ─► MinIO, after nginx asks the API to check the token
                  └─► /uploads ─► MinIO (presigned POST)
                         worker ◄── job queue: ffprobe, ffmpeg to HLS, thumbnail ──► MinIO
```

Снаружи доступен только nginx (или Caddy при `--domain`). API устроено по слоям: тонкие
роутеры, сервисы с логикой и модели; все правила ролей и видимости находятся в
`backend/app/core/permissions.py`. Очередь задач — это таблица PostgreSQL, из которой
задачи берутся через `SELECT ... FOR UPDATE SKIP LOCKED`.

### Безопасность вкратце

- Файлы приватных видео никогда не публичны: для воспроизведения и миниатюр нужен
  короткоживущий HMAC-токен, который выдаётся после проверки прав и который nginx просит
  API проверить при каждом запросе к медиа.
- Пароли хранятся через Argon2; токены доступа живут 15 минут и хранятся в памяти;
  refresh-токены ротируются с обнаружением повторного использования, в HttpOnly-cookie
  с SameSite=Strict.
- Лимиты запросов на клиента в nginx; строгая CSP и заголовки безопасности; загрузки
  проверяются через ffprobe, а не по имени файла; у воркера нет доступа в интернет.
- `install.sh` генерирует все секреты; `scripts/check-secrets.sh` проверяет, что в git их нет.

## Разработка

Makefile запускает отдельный стенд для разработки с горячей перезагрузкой; команда `make`
без аргументов выводит список всех целей.

```bash
make setup   # один раз: env-файлы, виртуальное окружение Python, пакеты фронтенда
make dev     # запуск; сайт и документация API на http://localhost:8080 и /docs
make seed    # демо-данные для dev-стенда; логины в demo-credentials.dev.txt
make check   # ruff, pytest и проверки фронтенда, обязательны перед каждым коммитом
make down    # остановка с сохранением данных
```

## Тесты

CI запускает всё это при каждом push (`.github/workflows/ci.yml`).

- `make check`: тесты бэкенда на настоящих PostgreSQL и MinIO и тесты фронтенда.
- `make smoke`: проверка запущенного стенда снаружи, через nginx, включая защиту
  воспроизведения.
- `scripts/test-install.sh`: запускает `install.sh`, дымовой тест и проверку демо-данных,
  затем запускает `install.sh` повторно и проверяет, что данные и секреты сохранились.
- `scripts/test-clean-install.sh`: запускает `install.sh` в «голом» контейнере Ubuntu и
  проверяет результат, включая демо-данные.
- `scripts/test-domain.sh`: запускает `install.sh --domain localhost` и проверяет HTTPS,
  редирект, HSTS, Secure-cookie и то, что nginx видит собственный адрес каждого клиента.
- `scripts/check-secrets.sh`: проверяет, что в git нет секретов ни в файлах, ни в истории.

## Как это было сделано

С помощью Claude Code, по плану из `docs/architecture.md`, шаг за шагом.

- `CLAUDE.md`: правила проекта: зафиксированный стек, слои, где находятся проверки прав,
  одна фича на коммит вместе с миграцией и тестами, Conventional Commits и вопрос ко мне
  перед любым изменением схемы или документа архитектуры.
- `.claude/commands/`: `/feature` (план, затем миграция, сервис, роутер и тест в каждом
  коммите, потом ревью), `/review` и `/commit`.
- `.claude/skills/`: `add-endpoint`, `db-migration` и `deploy-check` — рецепты для
  повторяющейся работы.
- `.claude/agents/`: `architect` для проектирования, `test-writer`, `reviewer`, который
  запускается на дифф каждого шага, и `security-auditor`, который запускается после работы
  над авторизацией, загрузкой и воспроизведением и перед сдачей. Их замечания и то, что
  было исправлено, описаны в сообщениях коммитов.
- `.claude/settings.json`: хук, запускающий ruff после каждой правки.
- `chat_history/`: папка с историей промптов. К сожалению, из-за технических проблем
  рабочее окружение было переключено на macOS, поэтому есть два zip-архива:
  1. youtube-clone-chat-history.zip
  2. -Users-yhlas-Desktop-youtube-clone.zip
